# Bilibili 签名编码器原型与词库审校稿

版本：`bili-literary-v1-draft1`。状态：**仅原型，词库未获人工审校通过，未开放账户绑定。**

## 当前可行性结论

技术上的容量关口已通过：三组候选分别具有大于 `2^80` 的合法句子空间，三组互不重叠；每句签名固定为 39 个 Unicode 字符、三个短分句。所有计数均已扣除禁配组合。运行时只读取版本化静态词库，不调用 LLM 或远程词库。

资料读取关口尚未通过。2026-10-01 对可控测试 UID `689985040` 的本地未登录公开资料读取可取得等级 5、粉丝数 418；Cloudflare 生产来源对 card 与 relation 接口实测均返回 HTTP 412。因此当前后端不能承诺从部署环境稳定读取最新签名，也未验证修改后的上游传播延迟。不能用本地可读、旧资料缓存或降级资料代替所有权验证成功。

本原型不创建挑战、不验证所有权、不写入账户绑定。需公开资料稳定读取和人工审校两项通过后，才能进入挑战与账户系统阶段。

## 模板与词库

每个短分句使用以下固定宽度模板：

`时间(2字) + 人物(2字) + 方式(2字) + 动作(2字) + 环境(2字) + 地点(2字)`

三个分句使用两个固定中文逗号和一个固定中文句号连接：`12 + 1 + 12 + 1 + 12 + 1 = 39`。标点无随机变体，所有词组均为两个可见 Unicode 字符，没有空格、不可见字符或隐含后缀。

三个子空间的首个分句时间词分别固定为“清晨”“黄昏”“深夜”，其余词槽由编码确定。三个前缀都是句子的可见语义部分。

## 精确计数

编译器以 BigInt 递推计算合法后缀数量，投影并缓存影响后续禁配的语义标签状态。当前只需 17 个计数状态，计数过程中没有浮点取整。

完整分句共有 `953458240` 种合法组合。对子空间 `i`，首个分句固定时间后的合法数为 `F_i`，后两个完整分句各有 `F` 种，故 `C_i = F_i × F × F`。

| 子空间 | 固定首词 | 精确合法句子数 | 容量位数下界 |
| --- | --- | ---: | ---: |
| 0 | 清晨 | 25881742059658679277977600 | 84 bit |
| 1 | 黄昏 | 27614468069978474885939200 | 84 bit |
| 2 | 深夜 | 27614468069978474885939200 | 84 bit |

`2^80 = 1208925819614629174706176`。全部合法句子数为 `81110678199615629049856000`。编码器选择每组其中严格 `2^80` 个不同句子，实际可达总数为 `3 × 2^80 = 3626777458843887524118528`。可用语法空间约 84 bit 不代表 nonce 具有 84 bit 随机熵；nonce 始终为 80 bit。

## 随机编码与单射证明

`crypto.getRandomValues` 生成 10 字节 nonce。每个候选先对同一 nonce 使用版本内固定的奇数仿射置换：`p = (a_i × n + b_i) mod 2^80`，再取合法句子编号 `r = floor(p × C_i / 2^80)`。

奇数与 `2^80` 互素，所以该置换是双射。由于 `C_i ≥ 2^80`，两个不同的 `p` 映射出的 `r` 至少相差 1。因此 nonce 到该子空间的编号是单射。编号转换使用 BigInt，既不截断成 JS Number，也不依赖随机模除达到 80 bit。

分句的 rank/unrank 遵循词库的固定顺序：某词组的区间宽度是该词组后合法后缀的数量。unrank 依次选择包含编号的区间，rank 累加所有先前区间的宽度；二者是严格逆运算。整句使用三个分句的混合进制编号。

每个词槽宽度固定、规范化后的词组互不重复，每个分句宽度固定、分隔符固定，因此字符串可唯一切分和还原。不同行编号不可能输出相同字符串。首个词组的三个固定前缀互不相同，因此三个子空间之间也没有交集。证明不依赖抽样未发现碰撞。

规范化固定为 NFC 后移除首尾空白；控制字符、不可见格式字符及换行分隔符直接拒绝。标点不替换，内部空白不折叠。输出本身已是规范形式、单行且无首尾空白。词库编译器拒绝重复词、规范化冲突、可变宽度词和含保留分隔符的词。

## 本地复现与测试

在 Auth 项目运行：

```powershell
node scripts/bilibili-compile.mjs
node --test tests/bilibili-encoder.test.mjs
```

第一条输出 JSON 报告，含真实 BigInt 容量、版本、完整带标签词库、禁配规则和固定 nonce 样本。第二条包含小型受限语法的全量穷举、独立方式重算实际容量、每个子空间的边界编号、规范化/Unicode 冲突拒绝、2048 个 nonce 的 6144 个候选往返和跨空间校验。容量结论来自精确计数及单射证明，随机抽样是回归检查。

原型模块 `src/bilibili/encoder.mjs` 导出：`ENCODER_VERSION`、`NONCE_LIMIT`、`capacityReport()`、`generateNonce()`、`generateCandidates(nonceHex)`、`normalizeSignature(text)`、`rankCandidate(index,text)`、`unrankCandidate(index,rank)`。

未来人工审校应形成可追踪的版本审批记录；若接入运行开关，`BILIBILI_LEXICON_REVIEWED_VERSION` 必须精确等于审批过的编码器版本，同时仍须满足公开资料读取的独立关口。当前没有配置此审批，也不应因为部署其他功能而顺便开放绑定。

后续新增短句模板可扩展编译器，但需要新版本、单独长度校验与空间互斥证明，不能为了保持标称 80 bit 忽略禁配或沿用旧报告。
